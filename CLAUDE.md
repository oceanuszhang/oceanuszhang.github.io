## What This Repo Is

An al-folio Jekyll academic portfolio site for Oceanus (Zhuoyang) Zhang, deployed to GitHub Pages at `https://oceanuszhang.github.io/`. Built on Jekyll 4.x with Ruby, Python (for Jupyter notebooks), and Node.js (for Prettier/PurgeCSS).

## Commands

### Local Development (Docker — recommended)

```bash
docker compose pull && docker compose up   # Start dev server at http://localhost:8080
docker compose up --build                  # Rebuild after Gemfile/Dockerfile changes
docker compose down                        # Stop and free port 8080
```

### Legacy (requires local Ruby + Python)

```bash
bundle install && pip install jupyter
bundle exec jekyll serve --port 4000
```

### Before Every Commit

```bash
# Install once:
npm install --save-dev prettier @shopify/prettier-plugin-liquid

# Run every time:
npx prettier . --write
```

Prettier is enforced by CI — PRs fail if files aren't formatted.

## Architecture

### How Pages Are Built

Jekyll assembles pages from three layers:

1. **Layouts** (`_layouts/*.liquid`) — outer HTML shell (e.g. `about.liquid`, `post.liquid`, `bib.liquid`, `cv.liquid`)
2. **Includes** (`_includes/`) — reusable Liquid components injected into layouts; `_includes/cv/` renders each CV section; `_includes/repository/` handles GitHub repo cards
3. **Content** (`_pages/`, `_posts/`, `_projects/`, `_news/`, `_teachings/`) — Markdown/Liquid files with YAML frontmatter

### Configuration Flow

`_config.yml` is the single source of truth for site-wide behavior:

- `url` + `baseurl` must match your deployment type (personal site: `baseurl:` empty; project site: `baseurl: /repo-name/`)
- Feature flags (`enable_darkmode`, `enable_math`, `enable_masonry`, etc.) control optional features
- `scholar:` block configures publication author highlighting — `last_name`/`first_name` must match BibTeX author strings exactly
- `third_party_libraries:` pins CDN versions and integrity hashes for all JS/CSS libraries

### Content Collections

| Directory                  | Purpose                | Naming                                   |
| -------------------------- | ---------------------- | ---------------------------------------- |
| `_posts/`                  | Blog posts             | `YYYY-MM-DD-title.md` (required)         |
| `_projects/`               | Project cards          | any `.md`                                |
| `_news/`                   | Homepage announcements | any `.md`                                |
| `_teachings/`              | Course pages           | any `.md`                                |
| `_bibliography/papers.bib` | Publications (BibTeX)  | standard BibTeX + al-folio custom fields |

### CV System

Two parallel CV formats are supported simultaneously:

- **RenderCV** (`_data/cv.yml`) — YAML format; auto-generates PDF via GitHub Actions (`render-cv.yml`)
- **JSONResume** (`assets/json/resume.json`) — standard JSON format
- Switch which format displays via `cv_format` frontmatter in `_pages/cv.md`

### Data Files (`_data/`)

- `socials.yml` — social media links; each entry has `name`, `link`, `icon`, `enabled`
- `coauthors.yml` — maps coauthor names to profile links (for publication pages)
- `venues.yml` — publication venue abbreviations
- `repositories.yml` — GitHub usernames/repos to display on repositories page

### Styling

- SCSS lives in `_sass/`; theme color is `--global-theme-color` in `_sass/_themes.scss`
- Available color variables are defined in `_sass/_variables.scss`

## Critical Pitfalls

**YAML in `_config.yml`:** Quote values containing `:`, `&`, or `#`. The `baseurl:` key must exist but be empty for personal sites — don't delete the key.

**BibTeX author matching:** `scholar.last_name` in `_config.yml` must match exactly how names appear in `.bib` entries for author highlighting to work.

**ImageMagick required:** The `jekyll-imagemagick` plugin generates responsive WebP images at build time. Docker handles this automatically; local builds need `brew install imagemagick` (Mac) or `sudo apt-get install imagemagick` (Linux).

**Never edit `gh-pages` branch** — it's auto-generated by the `deploy.yml` GitHub Action. All changes go to `main`.

**CSS/JS not loading after deploy:** Almost always a `url`/`baseurl` mismatch in `_config.yml`.

## al-folio Custom BibTeX Fields

Papers in `_bibliography/papers.bib` support extra fields beyond standard BibTeX:
`pdf`, `code`, `preview`, `abstract`, `slides`, `poster`, `video`, `website`, `arxiv`, `selected`, `award`, `bibtex_show`, `altmetric`, `dimensions`, `google_scholar_id`, `inspirehep_id`

These are stripped from rendered output via `filtered_bibtex_keywords` in `_config.yml`.
